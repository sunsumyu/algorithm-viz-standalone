src/algorithms/categories/dynamic-programming/dp-generated-renderers.ts (4,700 行 / 233 KB)
src/algorithms/categories/dynamic-programming/dp-demo-visualizer.ts (85 KB)
Before: 浅层单体挤压 (Shallow Monolith)
dp-generated-renderers.ts (4700 行)
• 硬编码 4 语种代码文本与行映射 (LINEAR_DP_CODES)
• 混杂 CSS 字符串与 DOM 拼装
• 各题硬编码步骤计算器 (linearSteps, arrayLinearSteps...)
• SVG 绘图函数与状态转移公式生成
✕ 接口即实现：新增或修改 1 道题需修改 4700 行单体文件，无接缝隔绝
调用方：dp-demo-visualizer / UI Panel
After: 深度领域求解引擎 (Deep DpSolver Module)
小型接口 Seam: executeDpAlgorithm(spec, input)
入参：算法规范定义 + 用户输入 ➔ 输出：标准化单步追踪流 DpTraceStep[]
深度实现 (Deep Implementation 隐藏在接缝后)
• 逐行调试步进器 • 多语言行号投影适配 • 状态转移树推导器 • 变量快照追踪器
✓ 算法定义独立为纯数据规范 Spec；引擎一次实现，各题复用

Problem：dp-generated-renderers.ts 将代码多语言配置、单步逻辑、HTML 样式及 SVG 渲染全部堆叠在 4,700 行的超大文件中，缺乏接缝与内聚性。

Solution：提炼深度 DpStepEngine 模块，将每道算法收敛为纯粹的数据规范适配器 (Algorithm Spec)，由引擎统一执行逐行单步生成与状态推演。

Wins：
  • ✓ Locality：各算法规格独立维护，互不干扰
  • ✓ Leverage：单步推导器跨全部动规题目复用
  • ✓ Interface shrinks：调用方只需传入 Spec 与输入
  • ✓ Testability：可在纯 Node/Vitest 环境脱离 DOM 测试步进
Strong in-process

Wins：
  • ✓ Locality：高亮与解释逻辑集中在代码模块

  • ✓ Interface shrinks：消除复杂的外部高亮入参转换
  • ✓ Deletion test：删除外部繁琐的行号解析代码
