问题 (Problem)

151 个独立 HTML 模板导致代码库极其浅层，修改统一规范（如去重框、对齐预设栏、输入框紧凑化）需要逐一遍历 151 处文件，极易漏改或引发 ID 脱节。

重构收益 (Wins)
  • Locality: 布局与边框规则 100% 收敛到单一呈现引擎，改一处处处生效
  • Leverage: 算法编写者只需专注数据推导算法（StepBuilder），零 HTML 样板
  • Deletion Test: 删除 151 个重复 HTML 模板，复杂度集中并大幅缩减体积
  • Testability: 统一接缝测试覆盖率由离散的 DOM 测试提升至单一组件级断言
Strong 强烈推荐 UI/Layout Seam

问题 (Problem)

许多历史算法的渲染器直接在 innerHTML 里写 background: #fff; border: 1px solid #e2e8f0;，导致在去掉了 HTML 模板的多层框后，渲染脚本又动态生成了子框。

重构收益 (Wins)
  • Locality: 消除渲染脚本硬编码的子卡片样式，样式接缝统一化
  • Zero Redundancy: 视口可用空间扩大 25% 以上，元素对齐更工整
  • Visual Purity: 彻底根除「框套框」问题，达到现代化顶级设计水准
Worth exploring 值得探索 Registry Seam

问题 (Problem)

元数据、动态 loader、渲染器分散在 3 个地方通过字符串 ID 弱关联，出现拼写差异（如 `my-queue` vs `implement-queue-using-stack`）时没有类型约束，导致白屏。

重构收益 (Wins)
  • Leverage: 单一事实源自动生成元数据与按需导入路由
  • Locality: 消除三处手工同步摩擦，杜绝白屏与未挂载 bug
