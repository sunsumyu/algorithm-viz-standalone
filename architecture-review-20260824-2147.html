当前视觉渲染与 UI 风格的 4 大摩擦点 (Friction Points)

视觉适配器硬编码样式类名 (Token Hardcoding)

GridVisualAdapter 中直接拼装固定 Tailwind 类名（如 bg-blue-100 border-2 border-blue-500）和特定小人 SVG。若要切换暗黑模式（Dark Mode）、赛博朋克（Cyberpunk）或学术线框风格，必须侵入修改 Adapter 内部代码。

布局风格依赖物理 HTML 分离 (Layout Fragmentation)

Lite 紧凑版与 Full 全景版目前依赖不同的 HTML 入口文件（*-lite.html vs *.html）。导致切换排版风格时需要进行整页 URL 跳转，无法在同一会话内实现无缝的 Layout 变体切换。

缺少统一的主题状态机与 CSS 变量系统 (No Theme Manager)

没有全局主题控制器（ThemeManager）来管理用户选中的主题 ID、色彩模式（Dark/Light）、动效开关（Playful / Minimal / Reduced-Motion），也没有使用 CSS 变量（CSS Custom Properties）解耦表现层。

模型特定视觉角色缺乏声明式契约 (No Avatar Contract)

不同算法题需要不同的语义角色（背包问题需要大盗/背包、爬楼梯需要青蛙/荷叶、网格需要探险家/机器人），目前角色动效与图标分散在 HTML 与 Adapter 中，无法在 YAML 模型中声明式配置。

1

提取 VisualThemeManager 视觉主题配置管理深模块

集中管理主题调色板（Light / Dark / Cyberpunk / Paper / Arcade）、CSS Variables 动态注入与持久化

🟢 Strong · 强烈推荐
📋 涉及模块与文件：
  • src/core/theme/visual-theme-manager.ts (NEW)
  • src/core/theme/theme-presets.ts (NEW)
  • src/styles/visualizer-theme.css (MODIFY)
🎯 解决方案 (Solution)：

将所有主题相关逻辑封装进 VisualThemeManager。定义语义化设计令牌契约（Tokens：--viz-bg-primary, --viz-cell-active, --viz-accent-color 等）。 外部仅需调用 themeManager.setTheme('dark-cyberpunk')，深模块内部自动向 DOM 根节点注入 CSS 变量与主题属性，并同步至 localStorage / URL Hash。

✨ 杠杆与收益 (Leverage & Locality)：
  • 单点高杠杆：新增一个主题只需要在配置表中增加一组 Tokens，所有视图与适配器自动生效。
  • 零泄漏：HTML 与 Adapter 不再关心具体颜色值，只引用语义类名或 CSS 变量。

2

将 GridVisualAdapter 改造为语义化视觉契约

消除 Adapter 内部硬编码 Tailwind 颜色类，改为语义化状态类名

🟢 Strong · 强烈推荐
📋 涉及模块与文件：
  • src/core/renderers/grid-visual-adapter.ts (MODIFY)
  • src/core/renderers/grid-visual-adapter.test.ts (MODIFY)
🎯 解决方案 (Solution)：

将网格单元格（Cell）与一维槽位（Slot）从硬编码类名重构成语义化状态标记：
• .viz-cell + .is-active / .is-source-top / .is-source-left / .is-obstacle / .is-done
所有的具体样式（边框光效、阴影、背景渐变、文字高亮）统一在 visualizer-theme.css 中由对应主题的 CSS 变量驱动。

✨ 杠杆与收益 (Leverage & Locality)：
  • 适配器纯粹化：Adapter 只负责“这是什么状态”，不负责“这个状态长什么颜色”。
  • 单测稳健性：单测只验证语义类名是否存在，不受 CSS 视觉调色板改版影响。

3

动态可配置布局容器（合并 Lite 与 Full 为统一自适应页面）

消灭 4 个 HTML 入口文件之间的物理隔离，支持配置级无刷新布局切换

🟡 Worth exploring · 值得探索
📋 涉及模块与文件：
  • src/core/visualizer-app-controller.ts (MODIFY)
  • stage-explorer.html (MODIFY - 设为主入口)
🎯 解决方案 (Solution)：

无需通过不同的 HTML 文件来区分 Lite 与 Full。在页面顶栏或配置面板提供【布局模式】切换按钮：
• data-layout="compact" (Lite 紧凑双卡模式)
• data-layout="panoramic" (Full 宽幅看板 + 变量矩阵)
• data-layout="zen" (专注纯画布模式)
由 CSS Grid 与 Controller 自适应控制 DOM 容器展现，切换瞬间保持播放状态与步数进度。

4

声明式 YAML 模型视觉角色与精灵（Avatar Sprite）规范化

在 YAML 中声明算法专属的 Character、Emoji 符号与重点色系

🟡 Worth exploring · 值得探索

在 YAML 模型规范中新增可选的 visualProfile 声明： 

visualProfile:
  themeAccent: "amber"          # 主色系: amber | blue | emerald | purple | rose
  character:
    walker: "adventurer-explorer" # 角色: adventurer | frog | robot | wizard
    cheerIcon: "🏆"
  sourceIndicators:
    primary: { icon: "🐱", label: "上方旧值" }
    secondary: { icon: "🐸", label: "左方新值" }

使得新增任何新的算法题时，视觉角色无需硬编码在 TS 或 HTML 中，完全由 YAML 规范声明驱动。
