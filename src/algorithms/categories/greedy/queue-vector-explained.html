Greedy / Queue Reconstruction

根据身高重建队列（vector 原理讲解）

本题已经有交互动画，这里补充 vector/数组插入的原理：为什么按身高降序、k 升序排序后，把每个人插入到下标 k 就能得到答案。

排序规则

先按照身高 从高到低 排序；身高相同时，按照 k 从小到大 排序。

people.sort((a, b) => {
  if (a[0] !== b[0]) return b[0] - a[0];
  return a[1] - b[1];
});

为什么先放高个？

当我们处理某个人 [h, k] 时，队列里已经存在的人都比他高或和他一样高。矮个之后再插入，不会增加他前面"身高大于等于 h"的人数。

插入到 k 的含义

当前队列全部是比当前人高或等高的人，所以插入下标 k，就保证他前面刚好有 k 个符合条件的人。

vector / 数组 splice 的过程

const queue = [];
for (const person of people) {
  // JS 数组 splice 与 C++ vector insert 类似：
  // 从 person[1] 位置插入，后面的元素整体右移
  queue.splice(person[1], 0, person);
}

数组/向量中间插入的代价是 O(n)，排序是 O(n log n)，总复杂度通常记为 O(n²)，空间复杂度 O(n)。

关键点：插入矮个不会影响高个的 k 值；这正是先处理高个的贪心正确性来源。理解 splice 的 O(n) 特质，有助于把握整体算法的时间复杂度。
