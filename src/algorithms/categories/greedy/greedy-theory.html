贪心算法理论基础

贪心算法每一步都做当前看起来最优的选择，并期望这些局部最优最终能组合成全局最优。它不像动态规划那样枚举所有状态，而是依赖问题本身的结构证明。

核心判断

  • 能否明确当前阶段的局部最优选择？
  • 局部最优做完后，后续问题是否仍保持同样结构？
  • 局部最优是否可以通过交换论证或反证法推出全局最优？

常见证明方式

  • 交换论证：把任意最优解逐步替换成贪心选择，答案不变差。
  • 反证法：假设不选贪心选择更优，推出矛盾。
  • 排序后决策：先建立顺序，再从左到右作不可回退选择。

适用题型

分配问题 区间问题 序列问题 买卖收益 覆盖范围

通用解题流程

  1. 拆分阶段：把问题转化为一系列可逐步决策的小阶段。
  2. 设计贪心策略：说明每个阶段选什么，例如"优先选终点最小的区间"。
  3. 模拟样例：用反例意识验证策略是否稳定。
  4. 证明正确性：用交换论证说明选择不会让答案变差。
  5. 实现细节：常见操作是排序、双指针、维护最大覆盖范围或累计正贡献。

代码骨架

function greedy(input) {
  // 1. 预处理：排序 / 统计 / 转换结构
  prepare(input);

  // 2. 维护当前阶段的信息
  let answer = initialValue;

  // 3. 从左到右做局部最优选择
  for (const state of input) {
    if (canTake(state)) {
      take(state);
      update(answer);
    }
  }

  return answer;
}
提示：贪心的难点通常不在代码，而在"为什么这么贪一定对"。如果找不到证明，优先尝试构造反例。
