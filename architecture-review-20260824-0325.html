现状问题 (Architectural Friction)

目前所有算法的写法（Java 顺推/逆推、内嵌 if / 外层 for 版、代码高亮行号、执行日志文本、各阶段副标题）全都作为脆弱的 HTML/JS 字符串硬编码在 2000 多行的单体文件中。

  • 违反 OCP（开闭原则）：每次想添加一种算法变体或调整日志，必须打开并改动核心渲染与推导代码；
  • 违反 DIP（依赖倒置原则）：高层 UI 逻辑直接依赖了底层的硬编码算法实现字符串，导致维护时极易改乱写好的算法；
  • 缺乏 Locality（局部性）：算法的知识（代码、步骤说明、阶段信息）与 UI 逻辑纠缠，改一处影响全局。

解决方案 (Proposed Deep Seam)

将所有算法变体与配置彻底外置到 unique-paths.yaml 中，建立强类型校验的 YamlSpecLoader 深模块：

  • 元数据层：题目 ID、名称、多语言描述、图例映射；
  • 演化阶段层：stage-1（递归）、stage-2（记忆化）、stage-3（二维DP）、stage-4（一维压缩）；
  • 方向维度：forward（顺推正序）与 reverse（逆推倒序）完全声明式配置；
  • 代码变体库：支持多语言与多样态（if / for / 递归辅助函数）的代码模板及语义锚点。

符合 LSP（里氏替换）的「通用多阶段状态转移执行引擎」

强烈推荐 (Strong)
涉及文件: src/core/universal-stage-engine.ts (新增多态执行中枢) src/algorithms/categories/dynamic-programming/engine/dp-step-engine.ts

现状问题

在每个阶段、每个方向中，都要手写一次 dfs(r, c)、for 循环和几十个 steps.push({...})。各个推导函数逻辑类似但又有微小差异，极难维护。

解决方案 (LSP 设计)

定义统一的 IAlgorithmExecutionModel。引擎根据 YAML 中声明的转移拓扑公式（如 dp[i][j] = left + up 或 memo[j] = down + right），自动驱动：

  • 递归树与调用栈追踪（自动生成 activeStack 与剪枝标记）；
  • 状态依赖关联（自动解析当前格引用的上方/左方/下方/右方单元格）；
  • 代码行号映射（通过语义锚点 @step:branch_left 等自动高亮，杜绝行号硬编码）。

构建标准模型模板与 YAML 驱动的可复用通用舞台

建议采纳 (Worth Exploring)

将「不同路径 (Unique Paths)」作为标准模型模板 (Gold Standard Model)。以后增加新题目（如 unique-paths-ii、minimum-path-sum、triangle、edit-distance 等）时： 零代码编写，仅需新建一个对应的 .yaml 配置文件，即可自动获得 4 阶段演化、多方向推导、动态树形生成、多变体代码高亮与交互控制器！

📄 拟提取的标准模型 YAML 结构设计 (unique-paths.yaml) 

id: unique-paths
name: "不同路径 (Unique Paths)"
category: "dynamic-programming"
icon: "🧭"
difficulty: "medium"
levelOrder: 5

directions:
  forward:
    label: "顺推 (正序)"
    start: [0, 0]
    target: [m - 1, n - 1]
    branches:
      - name: "down"
        delta: [1, 0]
        label: "向下探索"
      - name: "right"
        delta: [0, 1]
        label: "向右探索"
  reverse:
    label: "逆推 (倒序)"
    start: [m - 1, n - 1]
    target: [0, 0]
    branches:
      - name: "left"
        delta: [0, -1]
        label: "向左寻源"
      - name: "up"
        delta: [-1, 0]
        label: "向上寻源"

stages:
  stage-1:
    type: "recursion"
    title: "阶段 1: 朴素递归"
    timeComplexity: "O(2^(m+n))"
    spaceComplexity: "O(m+n)"
    code:
      java:
        forward: |
          class Solution {
              public int uniquePaths(int m, int n) {
                  return dfs(0, 0, m, n);
              }
              private int dfs(int i, int j, int m, int n) {
                  if (i == m - 1 || j == n - 1) return 1;
                  int down = dfs(i + 1, j, m, n);
                  int right = dfs(i, j + 1, m, n);
                  return down + right;
              }
          }
        reverse: |
          class Solution {
              public int uniquePaths(int m, int n) {
                  return dfs(m - 1, n - 1);
              }
              private int dfs(int i, int j) {
                  if (i == 0 || j == 0) return 1;
                  int left = dfs(i, j - 1);
                  int up = dfs(i - 1, j);
                  return left + up;
              }
          }
  stage-4:
    type: "space-optimized"
    title: "阶段 4: 一维空间压缩"
    variants:
      if:
        title: "内嵌 if 版"
        code:
          java: ...
      for:
        title: "外层 for 版"
        code:
          java: ...
