# Spec: 数字串翻译方案数(解码方法)f(s, i) 双模式可视化演示

> 正式发布副本,issue 位于 `.scratch/decode-ways/issues/001-decode-ways-visualizer.md`,标签:ready-for-agent
> 日期:2026-08-15

## Problem Statement

学习「数字串翻译/解码方法」(LeetCode 91) 这道经典动态规划入门题时,初学者难以在脑中同时追踪三件事:从左往右尝试模型 `f1(char[] s, int i)` 的递归展开过程、`s[i]=='0'` 与两位数 `<= 26` 这两个分支条件的实际取舍、以及暴力递归 O(2^n) 与一维 DP O(n) 之间的联系。项目里现有 DP 演示(dp-demo、fibonacci)都不覆盖这道题,用户希望按仓库既有的「步进生成器 + StepVisualizer + 注册清单」模式,新增一个交互式演示页面。

## Solution

新增一个「数字翻译方案数」算法演示页,收录 4~6 位示例数字串。页面提供两种可视化模式,Tab 切换:

1. **递归树模式**:SVG 递归调用树,节点标记 `f(i)`。随播放逐调用展开:每次节点分裂展示两条边——「取 1 位 `s[i]` → f(i+1)」与「取 2 位 `s[i..i+1]` → f(i+2)」(两位分支仅在存在且 `10 ≤ 值 ≤ 26` 时出现);回溯时在节点上回填返回值;同一 `(i)` 的重复子树以专用配色高亮,直观呈现指数级重复计算。两位分支边上直接标注被尝试的两位数字与其数值判定(✓ ≤26 / ✗ >26 / ✗ 越界)。
2. **DP 迭代模式**:一维 dp 数组从右往左填表(对应从 `f(n)=1` 出发倒推),dp 表格与上方数字串字符格纵向对齐;计算 `dp[i]` 时高亮依赖格 `dp[i+1]`(取 1 位)与 `dp[i+2]`(取 2 位),弧线箭头指向当前格,并给出数值代入公式(复用 dp-demo 的「数值代入徽章」与决策拆解卡片交互:`不选 s[i]` / `选 s[i..i+1]` / 结论)。数字串中的 `'0'` 字符格以醒目红色系标记「本位不可单独翻译」。

两个模式共享:顶部一体化的输入区(数字串输入框 + 开始按钮 + 示例 chips)、单一来源的统计徽章、底部播放控制条(重置/上一步/播放/下一步/计数/速度),右侧代码面板与当前步高亮联动。代码面板为双语言(Java 递归版 / Java DP 迭代版),随 Tab 切换更新,Java 递归版与截图源码逐行对应。

遵循仓库 `.agents/skills/ui-layout-design` 规范:主画布(SVG 树或 dp 表)占视口 60-70%,代码与日志并列于可收起侧栏,SVG 画布角落提供悬浮缩放(+/-)、聚焦(📍)、重置(🎯)控件。

## User Stories

1. 作为算法初学者,我想输入任意 1~10 位数字串并点击「开始」,以便查看这道题在我自己的输入上的完整推演。
2. 作为算法初学者,我想点击预设示例 chips(如 `226`、`11106`、`06`、`10`、`2126`),以便一键加载最能暴露边界情况的典型输入。
3. 作为算法初学者,我想在递归树模式中按「下一步」逐调用展开 `f(0)`,以便看清「从左往右尝试」是如何把大问题拆成子问题的。
4. 作为算法初学者,我想在树节点上看到当前下标 i 与该子串的返回值回填动画,以便理解递归的「展开 → 到底 → 回溯返回」全流程。
5. 作为算法初学者,我想看到两位数分支边上的标注(如 `26 ✓`、`27 ✗ >26`、`i+1 越界 ✗`),以便直观理解 `<= 26` 与边界判断在剪枝中的作用。
6. 作为算法初学者,我想看到 `s[i]=='0'` 时该分支返回 0 的红色节点与提示,以便理解为什么前导 0 / 独立 0 让方案数为 0。
7. 作为算法初学者,我想看到重复子问题(同参数 `f(i)` 多次展开)用统一颜色标出,以便明白暴力递归为何是指数级。
8. 作为刷题者,我想在统计徽章中看到「总调用数、重复子问题数、两位分支命中数」,以便量化重复计算的规模。
9. 作为刷题者,我想切换到 DP 模式看一维 dp 数组从右往左逐格填表,以便理解自底向上是如何消除重复子问题的。
10. 作为刷题者,我想在 DP 模式看到 `dp[i] = dp[i+1] + (两位可用 ? dp[i+2] : 0)` 的依赖箭头与数值代入,以便把公式和格子填充过程一一对应。
11. 作为刷题者,我想看到含 0 输入(如 `10`、`2101`、`06`)在 dp 表中触发的特殊路径,以便掌握 0 的特判逻辑。
12. 作为学习者,我想看到两个模式共享的最终答案徽章(方案总数)且数值一致,以便确认递归与 DP 殊途同归。
13. 作为学习者,我想在右侧代码面板看到当前执行行高亮,并随模式切换更换代码(递归版/迭代版),以便把动画与源码互相印证。
14. 作为学习者,我想看到 Java 递归代码与截图中的 `f1(char[] s, int i)` 完全一致,以便与课程/题解对照。
15. 作为演示者,我想用播放/暂停/速度滑杆自动播完整个推演,以便像放动画一样讲解。
16. 作为演示者,我想用「上一步」回退,以便在讲解出错时倒回去重讲某一步。
17. 作为演示者,我想在 SVG 树上缩放、拖拽平移、一键聚焦当前活跃节点、一键重置视图,以便在树变大时仍能看清局部。
18. 作为演示者,我想看到每一步的中文解说条与执行日志(含「f(2) 第二次展开 → 重复子问题」类事件),以便配合口头讲解。
19. 作为审查者,我想让超长输入(>10 位或非数字)被输入校验拦截并提示,以免递归树爆炸或生成错误步骤。
20. 作为审查者,我想让含 0 的非法输入(如 `06`、`100`)正确得出方案数 0 而不是崩溃,以便演示边界条件的价值。
21. 作为贡献者,我想让步进生成器是纯函数模块并被 vitest 覆盖,以便后续重构 UI 时不破坏算法正确性。
22. 作为贡献者,我想让该演示按 `registerAlgorithm` 清单注册进 dynamic-programming 分类并出现在关卡列表,以便用户能从目录导航进来。

## Implementation Decisions

- 按仓库既有模式新增三类文件:HTML 模板(玻璃拟态 + 蓝紫渐变,深色系)、renderer(继承 `StepVisualizer`)、以及步进生成器纯函数模块;renderer 尾部调用 `registerAlgorithm` 清单注册,`id` 定为 `decode-ways`,分类 `dynamic-programming`,难度 2。
- 步进生成器为**不依赖 DOM 的纯函数模块**,导出:递归步骤构造函数、DP 步骤构造函数、递归树节点结构(含父指针、分裂边标注、回填值、重复标记)。两种模式各持有独立的步骤数组与游标(参照 fibonacci 的双模式实现)。
- 递归树步骤沿用「调用栈深度 + 事件类型(call / branch-1 / branch-2 / return / base-case / dead-zero)」的事件流模型;树渲染采用增量绘制而非每步全量重建,以支撑 6 位输入下约百级节点。
- DP 模式方向为 `i` 从 `n` 递减到 `0`(与递归自顶向下镜像),dp 表与字符格纵向对齐;决策拆解卡片沿用 dp-demo 的 `DpDecisionBreakdown` 三分支结构(不选 / 选 / 结论),两位不可用时该分支置灰并给出原因。
- 代码面板提供 Java 递归版(与截图 `f1` 逐行一致)与 Java DP 迭代版两组行数组,Tab 切换时调用 `CodePanel.updateLines`。
- SVG 画布实现悬浮控件:缩放 +/-、聚焦当前活跃节点(📍)、重置视图(🎯),满足 ui-layout-design 第 4 条。
- 统计徽章为单一来源(不与任何面板重复):递归模式显示调用数/重复子问题数,DP 模式显示已填格数/当前公式,共享最终答案徽章。
- 输入约束:仅数字字符,长度 1~10;非法输入在输入框行内提示且不生成步骤。
- 引入 vitest 作为 devDependency,新增 `test` script;测试只针对步进生成器纯函数接缝(见 Testing Decisions),不测 DOM 渲染。

## Testing Decisions

- 唯一测试接缝:**步进生成器纯函数**(buildRecursiveSteps / buildDpSteps / 树结构)。好测试只断言外部可见行为:给定输入串,断言最终答案、步骤序列的完整性与一致性——不测内部循环结构、不测 DOM。
- 必备用例(来自 LeetCode 91 公认语义):`"226"→3`、`"12"→2`、`"0"→0`、`"06"→0`、`"10"→1`、`"100"→0`、`"2101"→1`、`"11106"→2`、`"111111"→13`。
- 步骤流不变量:首步为 init、末步为 done 且携带最终答案;递归与 DP 两种生成器对同一输入给出的最终答案一致;每个两位分支步骤携带的数值标注与输入串切片一致;`s[i]=='0'` 的 dead 分支步骤存在且返回 0。
- 树结构不变量:每个非根节点的父节点存在;同一 `i` 参数的第二次及以后展开被标记为重复。
- Prior art:仓库当前无测试;此模块为仓库第一组单元测试,vitest 配置以最小化接入(仅 `test` script,不改构建产物)。
- UI/渲染层验证仍走人工浏览器走查(与仓库现状一致),类型层面由 `npm run typecheck` 把关。

## Further Notes

- 截图原始 Java 递归代码(规格的权威对照,渲染器中的代码行须与其逐行对应):

```java
// s : 数字字符串
// s[i....]有多少种有效的转化方案
public static int f1(char[] s, int i) {
    if (i == s.length) {
        return 1;
    }
    int ans;
    if (s[i] == '0') {
        ans = 0;
    } else {
        ans = f1(s, i + 1);
        if (i + 1 < s.length && ((s[i] - '0') * 10 + s[i + 1] - '0') <= 26) {
            ans += f1(s, i + 2);
        }
    }
    return ans;
}
```
